# Техническое состояние проекта

Актуализировано 14 ноября 2026 года после разделения карточек по заданиям.

## Разделы сайта

- `/` — быстрые карточки.
- `/test/` — пробники по выбранным заданиям №1–26.
- `/theory/` — база знаний по 27 заданиям и самостоятельная практика сочинения.
- `/versions/` — история изменений.
- `/admin/` — серверная админка при размещении с Django.

GitHub Pages публикует статическую версию под префиксом `/linguae-Russicae/`.

## Карточки и объяснения

Каждое задание хранится в `cards/task-НОМЕР.js`. В одной записи находятся упражнение, ответ, варианты кнопок и поле `explanation`. Формат нормализует `cards/catalog.js`, затем данные использует `app.js`.

Задание 15 использует слова целиком. При обновлении сохраняйте числовой ID и `legacyId`. Данные, опубликованные через серверную админку, могут переопределить статическую запись.

Правки объяснений выполняются в файле соответствующего задания. Для Н/НН указываются часть речи, производящее слово при наличии и правило его написания. У производного существительного или наречия раскрывается также правило исходного прилагательного или причастия.

## Пробники

`test/bank.js` содержит первые два варианта Дощинского 2027. Остальные варианты 2027 и все варианты 2026 находятся в `test/doshchinsky-*/v*.json`. `test/bank-manifest.js` перечисляет варианты, `test/bank-loader.js` загружает их по необходимости. `exam-explanations.js` содержит дополнительные разборы ранних заданий.

Карточка и задание пробника имеют отдельные объяснения. Обновление одной записи не переносится автоматически в другую.

## База знаний

Канонический текст находится в `chapters/`. В `chapter-index.json` описаны главы, в `sources.json` — источники. У правил постоянные ID вида `R15-01`.

`python3 scripts/build_theory.py` обновляет опубликованный `theory/index.html`. `node knowledge-base/tools/build.cjs` проверяет данные и создаёт JSON/Markdown в игнорируемом `knowledge-base/generated/`.

Снимки словников в `data/` получены из карточек и датированы в метаданных. Они не объявляются полными официальными словарями нового экзаменационного года. Обновление через `node knowledge-base/tools/export-project-data.cjs` читает действующие банки карточек.

Изменение главы теории не переписывает объяснения карточек. При расхождениях сначала проверяйте правило по нормативному источнику, затем согласовывайте соответствующие записи.

## Проверки изменений

1. Создать резервную ветку от актуального состояния.
2. Редактировать канонические данные, сохраняя ID и ответы вне запрошенных изменений.
3. Выполнить подходящие тесты из `tests/`. Для изменений главы выполнить обе сборки базы знаний.
4. Проверить публичный артефакт командой `python3 tests/public-artifact.py`.
5. Если добавлены публичные ресурсы, включить их в `PUBLIC_FILES` в `server/content/views.py`.
6. Оформить pull request и дождаться проверок GitHub.

Серверные проверки выполняются командой `python manage.py test content` из `server/` с переменными окружения согласно [инструкции сервера](../server/README.md).

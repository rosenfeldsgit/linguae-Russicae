## Очистка истории

Действующих ключей не обнаружено: история не переписывалась. Если известен конкретный утёкший ключ, сначала отозвать/заменить его у провайдера, проверить использование и расходы. Затем очистить ВСЕ ветки и теги (включая backup) через git-filter-repo и согласованные обновления refs, проверить результат. Простое удаление строки новым коммитом утечку не устраняет. Копии PR, кэш и чужие клоны могут остаться: следовать инструкции GitHub. Резервные копии с утёкшими секретами хранить закрыто, не в публичной backup-ветке.

Перед изменениями создана backup/before-security-2026-11-11 и локальный git bundle со всеми доступными ветками. Базы данных работающего сервера здесь нет; резервирование кода не заменяет бэкап PostgreSQL.

## Что требует настройки площадки

- Изменения предложены отдельным PR: до merge и успешной публикации публичный сайт их не получает. Меры Nginx/Compose действуют только после развёртывания личного сервера.
- GitHub: включить 2FA/passkey, secret scanning/push protection, защиту main с обязательными проверками PR и запретом force push, проверить collaborators и активные токены. Эти настройки в этом PR не включены и не подтверждены.
- GitHub Pages: проверить источник публикации. `_config.yml` действует при стандартной сборке Jekyll из ветки. При публикации без Jekyll использовать `python3 scripts/build_public.py НОВЫЙ_КАТАЛОГ` и публиковать только этот каталог. Проверить после публикации, что служебные пути возвращают 404.
- GitHub Pages не даёт установить свой Nginx/межсетевой экран. Доступность зависит от платформы и её лимитов. HTTP-лимитирование в JavaScript не защитит хостинг.
- Для отдельного сервера: хостинг с upstream DDoS-фильтрацией, firewall (публично только 80/443; SSH по ключам с ограниченным доступом), обновления ОС, контроль диска/RAM/ошибок/срока сертификата, закрытая админка и регулярная проверка восстановления БД. Конкретный CDN и фильтры не настроены: неизвестны домен, площадка, ограничения доступности и бюджет.
- Ответы пробников скачиваются в браузер по устройству текущей тренировки. Это нормально для самоподготовки; для защищённого школьного экзамена нужна серверная проверка ответов и другая архитектура.

## Проверки

Локально: 12 тестов Django; 5 существующих проверок JS; отдельный тест сборки публичных файлов и всех HTML-ресурсов; pip-audit; git diff --check; сканер истории без вывода значений. Docker в рабочем окружении отсутствует: проверки Compose/Nginx/Caddy и локальная проверка ограничения входа/подмены X-Forwarded-For вынесены в отдельный CI job; до их успешного завершения контейнерная конфигурация не считается проверенной на запуск. Нагрузочные и DDoS-тесты публичного сайта не выполнялись.

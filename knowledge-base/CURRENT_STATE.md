# Техническое состояние проекта

Актуализировано 16 ноября 2026 года.

## Разделы сайта

- `/` — быстрые карточки.
- `/feed/` — случайная лента заданий с фильтром, поиском по ID и самопроверкой.
- `/test/` — пробники по выбранным заданиям №1–26.
- `/theory/` — база знаний по 27 заданиям и самостоятельная практика сочинения.
- `/versions/` — история изменений.
- `/edit/` — скрытый локальный редактор базы знаний: черновик браузера и экспорт JSON для переноса через чат.
- `/admin/` — серверная админка при размещении с Django.

Статический сайт опубликован на `https://rusalingvo.ru/` через GitHub Pages. Относительные ссылки также поддерживают размещение под префиксом `/linguae-Russicae/`.

## Карточки и объяснения

Каждое задание хранится в `cards/task-НОМЕР.js`. В одной записи находятся упражнение, ответ, варианты кнопок и поле `explanation`. Формат нормализует `cards/catalog.js`, затем данные использует `app.js`.

Задание 15 использует слова целиком. При обновлении сохраняйте числовой ID и `legacyId`. Данные, опубликованные через серверную админку, могут переопределить статическую запись.

Правки объяснений выполняются в файле соответствующего задания. Для Н/НН указываются часть речи, производящее слово при наличии и правило его написания. У производного существительного или наречия раскрывается также правило исходного прилагательного или причастия.

15 ноября 2026 года перепроверены 436 объяснений задания 11. У глаголов указываются конкретная форма «я» и сохранение/замена суффикса, отдельно рассматривается ударный -ва-. Для именных суффиксов указываются ударение, исходное слово или изменённая форма. Нельзя объяснять гласную правилом Н/НН или выдавать глагольное -ива- за -лив-. Состав проверки, контрольная сумма упражнений и смысловые регрессии зафиксированы в `tests/suffix-explanations.cjs`. Это обновление карточек и главы 11, а не отдельных объяснений полных заданий пробника.

## Пробники

`test/bank.js` содержит первые два варианта Дощинского 2027. Остальные варианты 2027 и все варианты 2026 находятся в `test/doshchinsky-*/v*.json`. `test/bank-manifest.js` перечисляет варианты, `test/bank-loader.js` загружает их по необходимости. `exam-explanations.js` содержит дополнительные разборы ранних заданий.

Карточка и задание пробника имеют отдельные объяснения. Обновление одной записи не переносится автоматически в другую.

16 ноября 2026 года добавлены первые 24 подробных разбора для лениво загружаемых банков: №4–15 варианта 3 Дощинского 2026 и 2027. Поля `explanation` и `explanationSources` хранятся рядом с заданием в JSON. Текст написан для конкретного условия с опорой на указанные нормативные источники; ключи и условия сохранены. Это первая порция, а не полное покрытие 1872 заданий. Состав и неизменность остальных данных проверяет `tests/seed-explanations.cjs`.

`test/exercises.js:renderExplanation` одинаково выводит разбор и ссылки в результатах пробника и в ленте. В ленте кнопка «Пояснение» появляется после проверки ответа при наличии разбора; редактирование ответа снова скрывает её. В пробнике разбор доступен в итогах через ⓘ. HTML из пояснений не исполняется, внешние ссылки разрешены только по HTTPS без логина/пароля. Переопределения администратора сохраняют приоритет; массово переписывать их статическими пояснениями нельзя.

## База знаний

Канонический текст находится в `chapters/`. В `chapter-index.json` описаны главы, в `sources.json` — источники. У правил постоянные ID вида `R15-01`.

`python3 scripts/build_theory.py` обновляет опубликованный `theory/index.html`. `node knowledge-base/tools/build.cjs` проверяет данные и создаёт JSON/Markdown в игнорируемом `knowledge-base/generated/`.

Снимки словников в `data/` получены из карточек и датированы в метаданных. Они не объявляются полными официальными словарями нового экзаменационного года. Обновление через `node knowledge-base/tools/export-project-data.cjs` читает действующие банки карточек.

Изменение главы теории не переписывает объяснения карточек. При расхождениях сначала проверяйте правило по нормативному источнику, затем согласовывайте соответствующие записи.

## Проверки изменений

1. Создать резервную ветку от актуального состояния.
2. Редактировать канонические данные, сохраняя ID и ответы вне запрошенных изменений.
3. Выполнить подходящие тесты из `tests/`. Для изменений главы выполнить обе сборки базы знаний.
4. Проверить публичный артефакт командой `python3 tests/public-artifact.py`.
5. Если добавлены публичные ресурсы, включить их в `public-files.json`.
6. Оформить pull request и дождаться проверок GitHub.

Серверные проверки выполняются командой `python manage.py test content` из `server/` с переменными окружения согласно [инструкции сервера](../server/README.md).

Лента заданий — самостоятельный раздел `/feed/` (`feed/index.html`, `feed/feed.js`, `feed/feed.css`). Общие рендерер, проверка и банк остаются в `test/`; JSON загружаются относительно адреса загрузчика. Старый `/test/feed.html` перенаправляет в ленту.

## Локальный редактор

`python3 scripts/build_editor.py` собирает `edit/index.html` и `edit/chapters.json` из канонических глав и того же рендерера, что `/theory/`. Выполнять после изменений глав и словников. Страница не связана с навигацией, содержит noindex и рассчитана на компьютер; адрес не является авторизацией.

Редактор не отправляет данные на сервер. Кнопка «Скачать изменения» создаёт `russian-knowledge-base-edits` schemaVersion 1: изменённые главы, пути исходников, originalMarkdown, originalHTML, editedHTML, читаемая editedMarkdown и исходные данные словника при наличии. Скачивание не очищает черновик. Перед применением сверить оригиналы с текущей базой, сохранить ID правил и проверить конфликты. Правки словников относятся к `dictionary.path`, правки теории — к `path`; карточки автоматически не обновляются. После применения выполнить обе сборки и тесты.

При щелчке по ячейке над таблицей появляется контекстная панель; вне таблицы она скрыта. Полей пикселей нет, размеры меняются за границы. Можно добавлять строки сверху/снизу и столбцы слева/справа, удалять выбранные строки и столбцы, выделять прямоугольник через Shift+щелчок, выделение текста или режим «Выделить ячейки», объединять и разделять ячейки. Объединение сохраняет весь текст; при разделении весь текст остаётся в первой ячейке. Enter в последней логической строке и Tab в последней ячейке добавляют новую строку; Shift+Enter даёт перенос внутри ячейки. Структурные операции входят в нативную историю Ctrl+Z. `table-model.js` обрабатывает rowspan/colspan и вставку внутри объединений; `tests/table-model.cjs` проверяет покрытие сетки и сохранность содержимого. Размеры и объединения сохраняются в editedHTML; Markdown — читаемая копия без полной геометрии. Существующие черновики восстанавливаются без сброса.

Таблицы ограничены шириной текстового блока и максимумом 52rem (832px при базовом шрифте 16px). Колонки сохраняются в процентах; изменение одной перераспределяет ширину остальных, не увеличивая общую. Старые пиксельные размеры в черновиках нормализуются с сохранением пропорций. Общие CSS-ограничения действуют в /theory/ и /edit/, включая перенос длинных слов.

Удаление строк/столбцов использует прямоугольник выбранных ячеек; кнопки показывают количество при групповом удалении. Частично затронутые объединения уменьшаются и сохраняют содержимое; полностью удалённые ячейки удаляются. Последняя строка или последний столбец удаляет всю таблицу, Ctrl+Z возвращает её. Клавиша Delete сохраняет стандартное редактирование текста.
